# Node „MPC” (pady Akai MPC Sample jako sterowanie) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Nowy node sterujący `MPC`, którego wyjścia (`hit`, `held`, `pad`) reagują na pady Akai MPC Sample przez USB MIDI i wpinają się kablem pod parametry efektów.

**Architecture:** Web MIDI (`navigator.requestMIDIAccess`) w oknie wizualizacji zapisuje stan padów do czystej klasy `MidiState` (stałe tablice, bez alokacji). `SignalBus.evaluate` czyta ten stan co klatkę i liczy obwiednie dla każdego node'a `MPC`. Proces główny dopuszcza uprawnienie `midi` dla okna, panel dostaje przycisk dodania node'a.

**Tech Stack:** Electron 44, TypeScript 5.9, Vitest, Web MIDI API.

**Spec:** `docs/superpowers/specs/2026-11-26-mpc-node-design.md`, dane sprzętowe w `docs/crt-bender/notatki-sprzet.md`.

## Global Constraints

- Repo `~/Projekty/crt-bender`, gałąź `crt-bender`. Oryginału `~/Projekty/git/desinger_visuals` nie ruszamy. Bez `push`.
- Pady: nuty **36–51**, pad N = nuta 35 + N (pad 1 = 36). Kanał nie jest filtrowany. Inne nuty ignorowane.
- Wiadomości: note on (0x9n, velocity 0 = note off), note off (0x8n), poly aftertouch (0xAn). Reszta ignorowana. Bez SysEx (`midiSysex` dalej odrzucany).
- Wyjścia `MPC` w zakresie 0..1: `hit`, `held`, `pad`. Parametry: `pad` (select: 0 = Wszystkie, 1–16 = Pad 1…16, domyślnie 0), `decay` (s, 0.05–3, krok 0.05, domyślnie 0.4), `gain` (0–4, krok 0.05, domyślnie 1).
- W pętli klatki nic nie alokujemy (zasada z CLAUDE.md).
- Etykiety po polsku, styl jak istniejące node'y. Commity: tytuł po polsku w trybie rozkazującym, `git add <ścieżki>`, na końcu `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Jeśli git nie ma tożsamości (`git config user.name` pusty), nie commituj, tylko zgłoś.

## Review Focus

4. Brak zgody albo brak Web MIDI (`requestMIDIAccess` odrzucone lub nieistniejące): okno działa dalej, wyjścia to zera. Test w Task 3.
5. Projekt zapisany z node'em `MPC` i wartością `pad` spoza 0–16 wczytany przez `sanitizeGraph`: wartość poprawiona, bez wywrotki. Test w Task 2.

### Task 2: Definicja node'a `MPC` i liczenie sygnałów

**Files:**
- Modify: `src/shared/nodes.ts` (`NodeType`, `NODE_DEFS` po `Math`)
- Modify: `src/renderer/src/engine/graph.ts` (`SignalBus.evaluate`, nowy `case 'MPC'`)
- Test: `src/renderer/src/engine/graph.test.ts`, `src/shared/graph.test.ts` (sanitize)

**Interfaces:**
- Consumes: `MidiState`, `PAD_COUNT` z Task 1.
- Produces: `NodeType` zawiera `'MPC'`. `SignalBus.evaluate(audio: AudioLevels, dt: number, midi?: MidiState): void`. Trzeci parametr jest opcjonalny, więc istniejące wywołania i testy się nie zmieniają. Brak `midi` daje zera na wyjściach `MPC`.

Definicja: `{ type: 'MPC', label: 'MPC', category: 'control', videoIn: false, videoOut: false, signalIn: [], signalOut: ['hit', 'held', 'pad'], params: [select 'pad' 'Pad' (0 „Wszystkie”, 1–16 „Pad 1”…„Pad 16”), num('decay', 'Wygasanie (s)', 0.05, 3, 0.05, 0.4), num('gain', 'Wzmocnienie', 0, 4, 0.05, 1)] }`.

Algorytm obwiedni (per node id, stan w `Map`, tworzony raz przy pierwszym spotkaniu node'a, nie co klatkę):
- „Nowe uderzenie” = licznik `hits` wybranego padu (albo suma po wszystkich dla `pad = 0`) większy niż zapamiętany. Siła = `velocity` tego padu (dla `pad = 0`: `velocity[lastPad]`). Przy pierwszej ocenie node'a tylko zapamiętaj liczniki, bez uderzenia.
- Nowe uderzenie: `env = velocity`. Inaczej: `env *= Math.exp(-dt * 4.6 / decay)` (po `decay` sekundach ok. 1%).
- `hit = clamp(env * gain, 0, 1)`; `held = clamp(p * gain, 0, 1)`, gdzie `p = pressure[pad-1]` albo max po wszystkich dla `pad = 0`; `pad = lastPad >= 0 ? lastPad / 15 : 0`.

- [ ] **Step 1: Write the failing tests** w `graph.test.ts`, nowy `describe('SignalBus – MPC')`. Graf: `defaultGraph()` + `createNode(g, 'MPC', …)` z `@shared/graph` (tak jak panel).
  - Brak `midi`: `values.get('<id>.hit') === 0`, `held === 0`, `pad === 0`.
  - Uderzenie `[0x90, 36, 127]` po pierwszej ocenie, potem `evaluate(audio, 1/60, midi)`: `hit ≈ 1`, `held ≈ 1`, `pad === 0`.
  - Wygasanie: po uderzeniu z velocity 127 i `decay = 0.4` ocena z `dt = 0.4` daje `hit < 0.011` i `hit > 0`.
  - `gain = 2` przy velocity 64 daje `hit ≈ min(1, 2 * 64/127)`.
  - Filtr: node A `pad = 1`, node B `pad = 2`, uderzenie w nutę 37: A `hit === 0`, B `hit > 0` (Review Focus 3).
  - `pad = 0` (wszystkie): uderzenie w nutę 51 daje `pad ≈ 1` i `hit > 0`.
  - Pierwsza ocena przy niezerowych `hits` (pad uderzony przed dodaniem node'a) nie daje `hit > 0`.
  - Kabel `MPC.hit` → parametr filtra działa przez `number()`, jak w istniejącym teście AudioIn.
  - W `src/shared/graph.test.ts`: `sanitizeGraph` z node'em `MPC` o `params: { pad: 99, decay: 10 }` zwraca node `MPC` z wartościami w zakresie definicji (Review Focus 5; sprawdź, jak `sanitizeParam` dziś traktuje select i number poza zakresem, i asercję dopasuj do tego zachowania).
- [ ] **Step 2: Run** `npx vitest run src/renderer/src/engine/graph.test.ts src/shared/graph.test.ts`. Expected: FAIL (`'MPC'` nie jest `NodeType`).
