# Dreamer w visualizerze: plan wdrożenia

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Trzy filtry Dreamera (Blur, Ziarno, Gradient) i node Wygładzanie, sterowane dźwiękiem z płynnymi przejściami, w metalicznie różowej skórce w stylu nodów CRT.

**Architecture:** Definicje w `src/shared/nodes.ts`, czysta logika (gradienty, wygładzanie, model Dreamera) w TS z testami, efekty jako własne `Pass`/`Effect` z `postprocessing` w `engine/dreamer/`, panel jako `DreamerNode` korzystający z części `crt/`.

**Tech Stack:** TypeScript 5.9, Three.js, `postprocessing`, GLSL (`?raw`), React 19, React Flow, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-26-dreamer-design.md`. Źródło algorytmów: `~/lightcraft/crates/pipeline/src/dreamer.rs` i `~/lightcraft/crates/develop/src/settings.rs` (`builtin_gradients`, `DreamerNoise`, `gradient_at`).

  - w `nodes.ts`: `interface GradientParamDef extends BaseParam { kind: 'gradient'; default: string }` w unii `ParamDef`

- [ ] **Step 1: Testy** w `gradient.test.ts`:
  - `encodeGradient(parseGradient(v)!) === v` dla każdego `GRADIENT_PRESETS[i].value`
  - `parseGradient('zzz')`, `''`, 17 stopów, `'0:12345g'`, `'NaN:000000'`, `'2:000000'` → `null`
  - `sampleGradient` Mono w `t=0.5` → `[0.5,0.5,0.5]` (±1e-6); `t=-1` → czerń, `t=2` → biel
  - Duotone: tuż przed 0.5 → `#101830`, w 0.5 i dalej → `#e0c090` (twardy)
  - jeden stop `'0.3:ff0000'` → czerwony dla każdego `t`; dwa stopy w tej samej pozycji → bez NaN
  W `graph.ops.test.ts`: `sanitizeParam` dla parametru gradientu przyjmuje poprawny string (zwraca go w postaci znormalizowanej przez `encode(parse())`), odrzuca `'zzz'`, liczbę i string dłuższy niż 400 (`undefined`).
