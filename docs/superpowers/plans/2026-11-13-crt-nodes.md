# Node'y CRT (Guns + Circuit): plan implementacji

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Cel:** dwa nowe filtry, `CRTGuns` i `CRTCircuit`. Efekt kineskopu liczony z 6 „napięć”. W edytorze grafu node'y mają własny wygląd analogowego efektu gitarowego, w stylu A albo B.

**Architektura:** fizyka zależna od czasu (synchronizacja, fazy, iskrzenie) jest w czystym TS (`engine/crt/model.ts`) i ma testy. Shadery GLSL tylko rysują. Guns to `Effect` z postprocessing. Circuit to własny `Pass` z buforem poświaty (ping-pong) i średnią jasnością z mipmapy. Panel renderuje `CrtNode` z pokrętłami, jackami i footswitchem.

**Stack:** TypeScript 5.9, three + postprocessing, React 19, @xyflow/react, Zustand, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-13-crt-nodes-design.md`. Wykonawca czyta spec razem z planem: wzory modelu są tam, a nie tutaj.

## Global Constraints

- Wszystkie 6 parametrów: `min 0`, `max 1`, `step 0.005`, `default 0.5`. 0,5 = sprawny telewizor.
- Klucze: `red`, `green`, `blue` (CRTGuns) i `hv`, `hdef`, `vdef` (CRTCircuit). Etykiety jak w specyfikacji.
- Zakres synchronizacji H/V: `|k − 0,5| ≤ 0,25`. Zapadnięcie pionu przy `vdef < 0,1`. Iskrzenie przy `hv > 0,85`, wygasa w 100 ms. Gaśnięcie przy `hv < 0,15`.
- Raster: `N = 288` linii. Pitch maski: 3 px. Poświata: `τ_G = 60 ms`, `τ_R = 40 ms`, `τ_B = 20 ms`.
- W `apply`, `CircuitModel.step` i `render` niczego nie alokuj (CLAUDE.md, wydajność).
- Renderer i panel nie importują `electron` ani modułów Node. `localStorage` tylko w try/catch.
- Po każdym zadaniu: `npm run typecheck`, `npm run lint`, `npm test`. Formatowanie: Prettier.
- Obszar: silnik i panel należą do agenta `react-ui` (router w CLAUDE.md).

## Review Focus

1. **Długie `dt` po powrocie z tła** (`dt` przycinane do 0,1 s w `renderer.ts`): fazy muszą zostać w `[0,1)`, a iskra nie może utknąć na 1. Test w zadaniu 1: `step(dt = 0.1)` × 1000 przy skrajnych pokrętłach daje `vPhase ∈ [0,1)`.
2. **Wartości spoza 0–1 z kabla** (Math potrafi wypuścić −5…5, ale `applyEdge` przycina do zakresu parametru): model i tak dostaje liczby z zakresu. Test w zadaniu 1: `step` z pokrętłami −1 i 2 nie zwraca NaN ani Infinity.
3. **Kilka instancji Circuit albo zmiana rozmiaru okna:** każda instancja ma własne bufory, a `setSize` je odtwarza bez wycieku. Weryfikacja ręczna w zadaniu 5: dwa Circuit w łańcuchu, zmiana rozmiaru okna, F11.
4. **Bypass ostatniego node'a CRT w łańcuchu** (CLAUDE.md: bypass przebudowuje przejścia): `CrtCircuitPass` musi respektować `renderToScreen`. Weryfikacja ręczna w zadaniu 5.
5. **Przeciąganie pokrętła na grafie** nie może przesuwać node'a ani zaznaczać obszaru (`nodrag`, `pointer capture`), a pokrętło z kablem nie przyjmuje przeciągania. Test logiki w zadaniu 4 (`dragValue`), interakcja ręcznie w zadaniu 5.

### Task 1: Model fizyczny CRT (czysty TS)

**Files:**
- Create: `src/renderer/src/engine/crt/model.ts`
- Test: `src/renderer/src/engine/crt/model.test.ts`

**Interfaces:**
- Produces:
  ```ts
  export const LOCK_RANGE = 0.25
  export interface GunUniforms { gain: number; convergence: number; overdrive: number }
  export function gunUniforms(v: number, out?: GunUniforms): GunUniforms
  export interface CircuitKnobs { hv: number; hdef: number; vdef: number }
  export interface CircuitUniforms {
    scaleX: number; scaleY: number   // wielkość obrazu, już z 1/√hvRatio (bez spadku pod obciążeniem)
    linH: number; linV: number; pincushion: number
    hvRatio: number                  // HV(k)/HV_nom = 0.5 + k
    brightness: number               // hvRatio · smoothstep(0.02, 0.15, hv)
    focus: number                    // = hvRatio
    jitter: number                   // drżenie linii w zakresie synchronizacji
    hDetune: number; hPhase: number  // 0 przy synchronizacji
    vRolling: number; vPhase: number // vRolling 0|1, vPhase ∈ [0,1)
    arc: number                      // 0..1
  }
  export class CircuitModel {
    readonly out: CircuitUniforms
    step(k: CircuitKnobs, dt: number, random: () => number): CircuitUniforms // zwraca this.out
  }
  ```

Stałe z mapowania (mogą być stroione później, testy sprawdzają zachowanie):
- `gain = 2v`, `convergence = v − 0.5`, `overdrive = max(0, 2v − 1)`.
- szerokość `0.5 + hdef`.
- wysokość: `vdef < 0.1 ? lerp(0.003, 0.6, vdef / 0.1) : 0.5 + vdef`.
- obie wymiary × `1/√hvRatio`.
- `linH = 0.3·(hdef − 0.5)`, `linV = 0.3·(vdef − 0.5)`, `pincushion = 0.2·|hdef − 0.5|`.
- rozstrojenie `d = |k − 0.5| − LOCK_RANGE`.
  - H: `hDetune = d > 0 ? sign·d·0.08 : 0`, `jitter = d > 0 ? 0 : 0.004·|k − 0.5|`, `hPhase = frac(hPhase + dt·hDetune·10)`.
  - V: `vRolling = d > 0 ? 1 : 0`, `vPhase = frac(vPhase + dt·sign·d·4)`. W synchronizacji `vPhase` wraca do 0.
- iskra: przy `hv > 0.85`, jeśli `random() < 20·(hv − 0.85)·dt`, to `arc = 1`, w przeciwnym razie `arc = max(0, arc − dt / 0.1)`.
- Wejście przycinane do `[0, 1]`.

- [ ] **Step 1: Napisz testy, które na razie nie przechodzą** (`model.test.ts`)
  - `gunUniforms(0.5)` → `{ gain: 1, convergence: 0, overdrive: 0 }`, `gunUniforms(1).overdrive === 1`, `gunUniforms(0).gain === 0`.
  - `nominal`: knobs 0,5/0,5/0,5, 100× `step(1/60, () => 0)` → `scaleX ≈ 1`, `scaleY ≈ 1`, `hDetune === 0`, `vRolling === 0`, `vPhase === 0`, `arc === 0`, `brightness ≈ 1`.
  - `vdef: 0` → `scaleY ≤ 0.005`.
  - `vdef: 0.9`: dwa kroki `dt = 0.1` → `vRolling === 1`, a `vPhase` jest różne w obu krokach.
  - `hdef: 0.7` → `hDetune === 0`, `jitter > 0`. `hdef: 0.9` → `hDetune > 0`. `hdef: 0.1` → `hDetune < 0`.
  - `hv: 0.8` daje mniejsze `scaleX` niż `hv: 0.5`. `hv: 0.05` daje `brightness < 0.1`.
  - Iskra: `hv: 0.95`, `step(1/60, () => 0)` → `arc === 1`, potem `step(0.11, () => 1)` → `arc === 0`. `hv: 0.8` z `random → 0` → `arc === 0`.
  - Review Focus 1: knobs `{hv: 1, hdef: 1, vdef: 0.9}`, 1000× `step(0.1, Math.random)` → `vPhase`, `hPhase` ∈ `[0, 1)`, `arc ∈ [0, 1]`.
  - Review Focus 2: knobs `{hv: -1, hdef: 2, vdef: -1}` → wszystkie pola `out` są skończone (`Number.isFinite`).
  - `step` zwraca ten sam obiekt (`toBe(model.out)`).

### Task 3: Node CRTCircuit i `CrtCircuitPass`

**Files:**
- Modify: `src/shared/nodes.ts`: `'CRTCircuit'`, `filter('CRTCircuit', 'CRT Circuit', [num('hv','Anoda HV',…), num('hdef','Odchylanie H',…), num('vdef','Odchylanie V',…)])`

- Modify: `src/renderer/src/engine/nodes/effects.ts` (`case 'CRTCircuit'`)
- Test: `effects.test.ts`, `nodes.test.ts`

**Interfaces:**
- Consumes: `CircuitModel`, `CircuitUniforms` (zadanie 1), `EffectHandle.pass` (zadanie 2).
- Produces: `export class CrtCircuitPass extends Pass { readonly model: CircuitModel; setKnobs(k: CircuitKnobs, dt: number): void }`. `apply` dla `CRTCircuit` czyta 3 parametry do jednego obiektu `CircuitKnobs` utworzonego raz i woła `pass.setKnobs(knobs, dt)`. `random = Math.random`.

Przejście w `render(renderer, inputBuffer, outputBuffer, dt)`:
1. `inputBuffer` → `lumaTarget` 64×64 (`generateMipmaps: true`, `LinearMipmapLinearFilter`). Shader kineskopu czyta `textureLod(luma, uv, 6.0)` jako `L̄`.
2. Shader kineskopu (`circuit.frag`): wejścia `inputBuffer`, `luma`, `prevPhosphor`, uniformy z `model.out`, `time`, `resolution`, `decay: Vector3 = exp(−dt/τ)`. Rysuje do `phosphor[i]`. Algorytm według specyfikacji (geometria → H/V synchronizacja → 2 linie Gaussa z `σ = σ₀(1+βI)/focus`, `σ₀ = 0.28` linii, `β = 0.6`, energia `∝ I/σ` → maska 3 px, tłumienie 0,35 → jasność × `brightness` × spadek HV `R = 0.25` → iskra `+ arc` → `max(nowa, prev·decay)`). Piksele poza obrazem i w pasach wygaszania są czarne.
3. Kopia `phosphor[i]` do `renderToScreen ? null : outputBuffer` (prosty `CopyMaterial` z postprocessing). Potem `i ^= 1`.
- `setSize(w, h)` odtwarza oba bufory poświaty (HalfFloat), `dispose()` zwalnia wszystkie cele i materiały.
